# whats-new-broadcast Specification

## Purpose

Эта capability определяет содержание и надёжность owner-only рассылки What’s New: каждый групповой чат получает актуальный текст со своей статистикой, а чаты с неудачной доставкой временно исключаются до появления новых сообщений.

## Requirements

### Requirement: Актуальное содержимое What’s New

Система MUST полностью заменять устаревший текст What’s New новым русскоязычным сообщением. Сообщение MUST описывать web-доступ с источниками, улучшенный контекст и поиск истории, а также распознавание изображений только по явному запросу пользователя, чтобы случайные фотографии не расходовали лимиты.

Новое сообщение MUST содержать таблицу сравнения лимитов «было → стало» и акцию со скидкой 20% на все платные тарифы до 31 августа 2026 года, 23:59 по Europe/Moscow. Сообщение MUST NOT содержать старые цены, старые значения лимитов, утверждение о сложении бесплатных и платных личных лимитов, `/terms` или `/paysupport`.

#### Scenario: Владелец просматривает новое сообщение перед рассылкой

- **WHEN** владелец вызывает owner-only команду What’s New
- **THEN** предпросмотр содержит только новый текст, актуальную таблицу «было → стало» и условия скидки до конца августа
- **AND** предпросмотр не содержит устаревшего описания подписки и команд `/terms` или `/paysupport`

#### Scenario: Новое сообщение отправлено в групповой чат

- **WHEN** рассылка успешно доставляет сообщение в активный групповой чат
- **THEN** пользователи получают тот же актуальный текст, который был подтверждён владельцем

### Requirement: Статистика конкретного группового чата

Система MUST формировать статистику отдельно для каждого чата, в который отправляется рассылка. В подписи сообщения MUST быть указано, сколько сообщений Ио ответила и сколько голосовых сообщений и кружков распознала именно в этом чате.

Счётчик ответов MUST учитывать сохранённые сообщения целевого чата, отправленные ботом и связанные с ответом через `replyToMessageId`. Счётчик голосовых MUST учитывать сохранённые входящие сообщения целевого чата типа `VOICE`, отправленные не ботом, сохраняя текущую семантику статистики распознавания.

#### Scenario: Два чата имеют разную статистику

- **WHEN** в двух активных группах сохранено разное количество ответов Ио и голосовых сообщений
- **THEN** каждое сообщение What’s New содержит значения, рассчитанные только по соответствующему чату
- **AND** статистика одного чата не попадает в сообщение другого

#### Scenario: Предпросмотр создаётся до начала рассылки

- **WHEN** владелец подтверждает предпросмотр, рассчитанный для набора активных чатов
- **THEN** при отправке каждому чату сохраняется per-chat статистика из его собственного набора сообщений
- **AND** общий текст и индивидуальные значения не требуют отдельной ручной настройки владельцем

### Requirement: Активность чата ограничивает рассылку

Система MUST хранить для каждого чата признак `active`, по умолчанию равный `true`, и nullable-момент `inactiveSince`. В список целей What’s New MUST попадать только групповые чаты с `active = true`.

#### Scenario: Новый или существующий чат имеет значение по умолчанию

- **WHEN** создаётся новая запись чата или применяется миграция к существующим чатам
- **THEN** чат считается активным, если он не был явно деактивирован
- **AND** ранее существующие чаты не теряются из списка рассылки

#### Scenario: Неактивный чат исключён из следующей рассылки

- **WHEN** у чата `active = false`
- **THEN** следующая рассылка не пытается отправить в него сообщение
- **AND** этот чат не увеличивает число целей, которым выполняется попытка доставки

### Requirement: Ошибка доставки деактивирует чат

Если все варианты отправки What’s New в конкретный чат завершаются ошибкой, система MUST сохранить для этого чата `active = false` и `inactiveSince` равным моменту деактивации. Ошибка одного чата MUST NOT останавливать последовательную рассылку в остальные активные чаты.

#### Scenario: Сообщение не доставлено в чат

- **WHEN** отправка через доступные варианты форматирования завершается ошибкой
- **THEN** чат помечается неактивным и получает момент `inactiveSince`
- **AND** текущая рассылка продолжает обработку остальных чатов
- **AND** итоговый отчёт считает этот чат недоставленным

#### Scenario: Сообщение успешно доставлено

- **WHEN** один из вариантов отправки успешно доставляет сообщение
- **THEN** чат не деактивируется
- **AND** он остаётся доступным для следующей рассылки

### Requirement: Ежедневное восстановление неактивных чатов

Система MUST не реже одного раза в сутки проверять неактивные групповые чаты. Если в таком чате есть сохранённое сообщение с `sentAt` позже `inactiveSince`, система MUST очистить `inactiveSince` и вернуть `active = true`. Сообщения, созданные до `inactiveSince`, MUST NOT реактивировать чат.

#### Scenario: В неактивном чате появились новые сообщения

- **WHEN** ежедневная проверка находит сообщение после момента деактивации
- **THEN** чат снова становится активным
- **AND** он попадает в следующую рассылку What’s New

#### Scenario: В неактивном чате нет новых сообщений

- **WHEN** ежедневная проверка не находит сообщений после `inactiveSince`
- **THEN** чат остаётся неактивным
- **AND** попытка отправки в него не выполняется

### Requirement: Сохранение защиты и отчётности рассылки

Система MUST сохранить owner-only доступ к предпросмотру и подтверждению, одноразовое подтверждение перед отправкой, последовательную отправку по целям и уведомление владельца с количеством целей, успешных доставок и недоставленных сообщений.

#### Scenario: Неавторизованный пользователь вызывает What’s New

- **WHEN** команду вызывает пользователь не из разрешённого private-чата владельца
- **THEN** предпросмотр и рассылка не выполняются

#### Scenario: Рассилка завершена после смешанного результата

- **WHEN** часть активных чатов получает сообщение, а часть возвращает ошибку
- **THEN** владелец получает итоговые количества всех целей, успешных доставок и недоставленных чатов
