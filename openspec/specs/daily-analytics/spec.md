# daily-analytics Specification

## Purpose

Даёт владельцу бота единый способ получать дневную аналитику активности, AI-ответов, найденных фактов и качества используемого контекста.

## Requirements

### Requirement: Владелец может запросить текущую аналитику вручную

Система MUST обрабатывать команду `/analytics` только в личном чате владельца, определяемого `ANALYTICS_CHAT_ID`. Команда MUST возвращать агрегированный отчёт за текущий день по часовому поясу `Europe/Moscow` и MUST NOT помечать автоматический отчёт дня как отправленный.

#### Scenario: Владелец запрашивает отчёт в личном чате

- **WHEN** владелец отправляет `/analytics` в личном чате
- **THEN** бот отправляет ему отчёт с начала текущего московского дня до момента запроса

#### Scenario: Другой пользователь отправляет команду

- **WHEN** пользователь, отличный от владельца, отправляет `/analytics`
- **THEN** бот не отправляет аналитический отчёт

#### Scenario: Команда отправлена в группе

- **WHEN** `/analytics` отправлена в групповом чате, даже если отправитель является владельцем
- **THEN** бот не отправляет аналитический отчёт в группу

#### Scenario: Ручной отчёт запрошен после вечернего отчёта

- **WHEN** автоматический отчёт за день уже отправлен, а владелец запрашивает `/analytics`
- **THEN** бот отправляет свежий ручной отчёт и не создаёт повторную автоматическую отправку

### Requirement: Отчёт содержит дневные показатели активности

Автоматический и ручной отчёты MUST содержать количество сохранённых входящих сообщений, уникальных чатов и уникальных отправителей, от которых бот увидел сообщения, а также уникальных чатов и отправителей, которым бот отправил связанные ответы.

#### Scenario: В отчёте есть активность чатов и пользователей

- **WHEN** в течение дня были сохранены входящие сообщения и ответы бота
- **THEN** отчёт содержит отдельные счётчики увиденных чатов, отвеченных чатов, увиденных пользователей и пользователей с ответом

#### Scenario: В отчёте нет активности

- **WHEN** за день отсутствуют соответствующие записи
- **THEN** каждый счётчик отображается как `0`, а отчёт всё равно отправляется владельцу

### Requirement: Отчёт содержит AI- и пользовательскую аналитику

Отчёт MUST содержать количество дорогих и дешёвых завершённых AI-ответов с разбивкой по точным идентификаторам моделей, количество запусков пользовательской аналитики, количество новых найденных фактов, количество использованных в ответах фактов, а также существующие показатели распознавания изображений, голосовых сообщений, покупок, возвратов и активных подписок.

#### Scenario: Ответы выполнены разными моделями

- **WHEN** в течение дня сохранены ответы, выполненные основной и fallback-моделью
- **THEN** отчёт разделяет их на дорогие и дешёвые и показывает точный `modelId` каждой модели

#### Scenario: Факт создан и использован

- **WHEN** в течение дня создан новый `UserFact` и один из фактов использован в ответе
- **THEN** отчёт увеличивает счётчики найденных фактов и использованных фактов отдельно

### Requirement: Исходящее AI-сообщение сохраняет модель

Каждое успешно сохранённое исходящее AI-сообщение в `Message` MUST содержать точный идентификатор модели провайдера в nullable-поле `modelId`. Входящие сообщения, старые записи и исходящие сообщения, не созданные AI-ответом, MUST сохраняться с `modelId = NULL`.

#### Scenario: Основная модель отправила ответ

- **WHEN** AI-ответ успешно доставлен и сохранён в `Message`
- **THEN** `Message.modelId` содержит идентификатор основной модели, использованной для генерации

#### Scenario: Fallback-модель отправила ответ

- **WHEN** AI-ответ после исчерпания основной квоты успешно доставлен и сохранён в `Message`
- **THEN** `Message.modelId` содержит идентификатор дешёвой fallback-модели

#### Scenario: Старое или не-AI сообщение

- **WHEN** отчёт рассматривает сообщение, созданное до миграции или не являющееся AI-ответом
- **THEN** такое сообщение не классифицируется как ответ по модели

### Requirement: Векторный контекст учитывается по московскому дню

Система MUST считать количество поисков векторного контекста, количество поисков с результатами и количество результатов, добавленных в AI-контекст. Счётчики MUST обнуляться при наступлении 00:00 по `Europe/Moscow`, ручной отчёт MUST только читать их, а не сбрасывать.

#### Scenario: Векторный поиск добавил результаты

- **WHEN** поиск вернул сообщения для пользовательского или чатового контекста и они добавлены в prompt
- **THEN** счётчик увеличивается на фактическое количество добавленных результатов

#### Scenario: Наступил новый московский день

- **WHEN** московская дата изменилась на 00:00
- **THEN** новый отчёт начинает векторные счётчики с нуля

#### Scenario: Процесс перезапущен до конца дня

- **WHEN** приложение перезапущено после начала московского дня
- **THEN** runtime-счётчики начинают заново и отчёт явно помечает их как значения с момента запуска процесса

### Requirement: Отчёт показывает операционное качество

Отчёт MUST показывать количество успешных AI-ответов, неуспешных попыток генерации, response rate для обработанных входящих запросов и среднее с p95 latency. Runtime-показатели, которые нельзя восстановить из базы после рестарта, MUST быть помечены как неполные за день.

#### Scenario: AI-ответ завершился ошибкой

- **WHEN** генерация AI-ответа завершилась ошибкой до успешной доставки
- **THEN** счётчик неуспешных попыток увеличивается, а успешный ответ не добавляется

#### Scenario: Отчёт содержит latency

- **WHEN** за период есть завершённые AI-ответы с измеренным временем обработки
- **THEN** отчёт содержит среднее и p95 время ответа в миллисекундах

### Requirement: Отчёт не раскрывает содержимое пользовательских данных

Аналитика MUST отправлять только агрегированные значения и названия безопасных категорий. Отчёт MUST NOT содержать тексты сообщений, содержимое фактов, prompts, AI-ответы, Telegram ID пользователей или сырые результаты векторного поиска.

#### Scenario: В отчёт попал факт или vector context

- **WHEN** система формирует отчёт после анализа фактов или векторного поиска
- **THEN** в отчёт попадают только количества, без текста и идентификаторов исходных данных
