# user-data-boundaries Specification

## Purpose

Определяет, какие сведения о пользователе разрешено добавлять в AI-контекст и возвращать через tools, чтобы упоминание или участие в одном чате не открывало личные данные из других чатов.

## Requirements

### Requirement: Персональные данные имеют явную область видимости

Система MUST добавлять в AI-контекст текущего запроса глобальные личные факты и память только текущего отправителя. Для другого пользователя система MUST NOT добавлять личную память и MUST включать только те факты, для которых существует подтверждённый публичный источник в текущем чате. Общая память чата MUST выбираться только по идентификатору текущего чата.

#### Scenario: Текущий пользователь продолжает личный диалог

- **WHEN** система формирует AI-контекст для сообщения текущего пользователя
- **THEN** она может использовать личную память и факты этого пользователя согласно действующим правилам private mode

#### Scenario: В сообщении упомянут другой пользователь

- **WHEN** текст содержит `@username` или `text_mention` другого пользователя
- **THEN** личная память этого пользователя и факты без публичного источника в текущем чате не попадают в AI-контекст

#### Scenario: В текущем чате есть подтверждённый публичный факт

- **WHEN** факт другого участника подтверждён публичным сообщением этого участника в текущем чате
- **THEN** система может включить этот факт без данных из иных источников и чатов

#### Scenario: Загружается общая память чата

- **WHEN** система добавляет shared memory в AI-контекст
- **THEN** выбираются только записи текущего чата

### Requirement: Запрос сведений о другом пользователе требует текущего участия

Система MUST подтверждать через Telegram, что запрошенный пользователь сейчас является участником текущей группы. Историческое сообщение, глобальный username или известный ID MUST NOT считаться достаточным подтверждением. При невозможности подтвердить участие система MUST отказать без раскрытия персональных данных.

#### Scenario: Запрошен текущий участник группы

- **WHEN** Telegram подтверждает, что другой пользователь сейчас состоит в текущей группе
- **THEN** tool возвращает базовый профиль и только факты с публичным источником в этой группе без личной памяти

#### Scenario: Пользователь покинул группу

- **WHEN** в базе осталось его сообщение, но Telegram сообщает, что пользователь больше не участник
- **THEN** tool не возвращает его факты или память

#### Scenario: Проверка участия недоступна

- **WHEN** Telegram API не позволяет подтвердить текущий статус пользователя
- **THEN** система возвращает безопасный отказ и не использует данные из базы как fallback авторизации

### Requirement: Ошибка определения области данных закрывает доступ

Система MUST NOT расширять область данных при ошибке чтения, разрешения username или проверки источника факта. Ошибка MUST быть наблюдаемой без записи содержимого памяти или факта в лог.

#### Scenario: Не удалось разрешить упоминание

- **WHEN** username не найден или запрос репозитория завершился ошибкой
- **THEN** система не добавляет пользователя и его данные в контекст

### Requirement: Псевдонимы не расширяют область пользовательских данных

Система MUST хранить, искать и передавать псевдонимы и предпочтения обращения только в пределах чата, где они получены или явно заданы. Автоматические наблюдения MUST иметь публичные источники этого чата; приватные сообщения, их reply-контекст и ответы бота MUST NOT использоваться для обучения. Система MUST NOT переносить псевдонимы из лички или другой группы в текущую группу даже для текущего отправителя. Разрешение ID по имени MUST NOT заменять существующую авторизацию: информация о другом пользователе, включая его псевдонимы и сведения в списке кандидатов, доступна через `get_user_info` только после подтверждения текущего участия через Telegram. Исторический поиск MUST оставаться ограниченным публичными сообщениями текущего чата.

#### Scenario: Имя известно только в другой группе
- **WHEN** в текущем чате ищут псевдоним, известный только из другой группы или лички
- **THEN** система не использует эту связь и не раскрывает её

#### Scenario: Проверка участия недоступна
- **WHEN** псевдоним разрешился в ID, но Telegram не подтверждает текущее участие при запросе сведений о другом человеке
- **THEN** система не раскрывает его профиль, псевдонимы или факты и не подменяет проверку историческим сообщением

#### Scenario: Приватный родитель публичного reply
- **WHEN** анализируемое публичное сообщение ссылается на private-сообщение
- **THEN** private-родитель исключается из контекста извлечения и не становится доказательством псевдонима

### Requirement: Явное управление обращением принадлежит самому пользователю

Система MUST разрешать изменение псевдонима и обращения только для текущего отправителя и текущего чата по его явной просьбе. Указанный в тексте чужой ID, цитата и чужое сообщение MUST NOT давать право менять предпочтения другого пользователя. В guest/read-only режиме запись MUST быть недоступна. Явная просьба в private mode MUST считаться намеренным persistent действием для текущего чата, аналогично явному сохранению памяти, и MUST NOT включать автоматическое обучение или публиковать настройку в другие чаты. Очистка временного private-сообщения MUST NOT удалять намеренно сохранённое предпочтение или запрет.

#### Scenario: Просьба переименовать другого участника
- **WHEN** пользователь просит назначить другому участнику предпочтительное обращение или передаёт его ID
- **THEN** система не изменяет чужую настройку и не применяет эту просьбу к отправителю по ошибке

#### Scenario: Явное сохранение в private mode
- **WHEN** пользователь в private mode просит «называй меня Саша»
- **THEN** предпочтение сохраняется для текущего личного чата и переживает очистку исходного private-сообщения
- **AND** оно не появляется в группах и автоматические наблюдения из private-сообщения не создаются

#### Scenario: Запрос с ограничением на запись
- **WHEN** запрос обрабатывается в guest/read-only режиме
- **THEN** пользовательские псевдонимы могут читаться только по разрешённому scope, а tool изменения обращения недоступен
