# image-recognition Specification

## Purpose

Распознавание изображений через vision API (RouterAI) с автоматическим поиском фото в цепочке reply сообщений Telegram. Система ходит по reply chain до 10 уровней, используя как Telegram API, так и базу данных, чтобы найти изображение в контексте запроса пользователя к боту. Распознавание происходит только для фото, связанных с запросом через reply, что экономит квоту IMAGE и предотвращает обработку случайных изображений в чате.

## Requirements

### Requirement: Распознавание только в треде запроса

Система SHALL распознавать изображения только если они находятся в цепочке reply запроса пользователя к боту.

#### Scenario: Фото с подписью-запросом

**GIVEN** пользователь отправляет фото с подписью "ио, что на картинке?"  
**WHEN** бот обрабатывает сообщение  
**THEN** система распознаёт изображение  
**AND** расходует квоту IMAGE  
**AND** бот отвечает с описанием изображения

#### Scenario: Фото без запроса к боту

**GIVEN** пользователь отправляет фото с подписью "вот моя собака"  
**WHEN** бот обрабатывает сообщение  
**THEN** система НЕ распознаёт изображение  
**AND** квота IMAGE НЕ расходуется  
**AND** бот НЕ отвечает

### Requirement: Поиск фото в цепочке reply (multi-hop)

Система SHALL ходить по цепочке reply до maxDepth уровней для поиска изображений. На каждом уровне система MUST проверить медиа текущего сообщения до перехода к родителю или завершения обхода.

#### Scenario: Фото в непосредственном reply

**GIVEN** Пользователь_А отправляет фото с подписью "смотрите"  
**AND** Пользователь_Б отправляет "ио, что это?" как reply на сообщение Пользователя_А  
**WHEN** бот обрабатывает запрос Пользователя_Б  
**THEN** система находит фото в reply_to_message  
**AND** распознаёт изображение  
**AND** бот отвечает с описанием

#### Scenario: Фото через 2 уровня reply

**GIVEN** Пользователь_А отправляет фото с подписью "смотрите чего тут"  
**AND** Пользователь_Б отправляет "интересно" как reply на сообщение Пользователя_А  
**AND** Пользователь_В отправляет "ио, расскажи что это" как reply на сообщение Пользователя_Б  
**WHEN** бот обрабатывает запрос Пользователя_В  
**THEN** система ходит по цепочке: В → Б → А  
**AND** находит фото в сообщении А  
**AND** распознаёт изображение  
**AND** бот отвечает с описанием

#### Scenario: Фото через 3+ уровня reply

**GIVEN** цепочка из 4 сообщений: А(фото) → Б(текст) → В(текст) → Г(запрос "ио")  
**WHEN** бот обрабатывает запрос Г  
**THEN** система ходит по цепочке: Г → В → Б → А  
**AND** находит фото в сообщении А  
**AND** распознаёт изображение  
**AND** бот отвечает с описанием

#### Scenario: Фото находится за пределом maxDepth

**GIVEN** фото находится глубже разрешённого maxDepth в reply chain  
**WHEN** система ищет фото  
**THEN** обход завершается на maxDepth  
**AND** фото не распознаётся

### Requirement: Использование БД для недоступных сообщений

Система SHALL использовать БД (таблицу Message) для получения reply_to_message, если Telegram API не вернул его. Загруженное из БД текущее сообщение MUST быть проверено на фото до проверки наличия replyToMessageId.

#### Scenario: reply_to_message доступно через API

**GIVEN** пользователь отправляет запрос с reply на недавнее сообщение  
**WHEN** система ищет фото в цепочке  
**THEN** использует ctx.msg.reply_to_message из Telegram API  
**AND** НЕ обращается к БД

#### Scenario: reply_to_message недоступно через API

**GIVEN** пользователь отправляет запрос с reply на старое сообщение  
**AND** ctx.msg.reply_to_message.reply_to_message отсутствует  
**WHEN** система ищет фото в цепочке  
**THEN** запрашивает replyToMessageId из таблицы Message  
**AND** загружает родительское сообщение из БД  
**AND** проверяет поле media на наличие image/jpeg

#### Scenario: Корневое фото из БД не имеет родителя

**GIVEN** последняя доступная запись reply chain загружена из БД  
**AND** её media содержит image/jpeg  
**AND** её replyToMessageId отсутствует  
**WHEN** система обрабатывает эту запись  
**THEN** она находит фото до завершения обхода  
**AND** использует сохранённое media для распознавания или кэша

### Requirement: Проверка shouldRespond перед резервированием квоты

Система SHALL проверять, требуется ли ответ бота (shouldRespond), ДО резервирования квоты IMAGE.

#### Scenario: :photo хэндлер с запросом

**GIVEN** пользователь отправляет фото с подписью "ио, опиши"  
**WHEN** :photo хэндлер обрабатывает сообщение  
**THEN** проверяет shouldRespond = true (подпись начинается с "ио")  
**AND** резервирует квоту IMAGE  
**AND** распознаёт изображение

#### Scenario: :photo хэндлер без запроса

**GIVEN** пользователь отправляет фото с подписью "вот фотка"  
**WHEN** :photo хэндлер обрабатывает сообщение  
**THEN** проверяет shouldRespond = false  
**AND** НЕ резервирует квоту IMAGE  
**AND** НЕ распознаёт изображение  
**AND** завершает обработку

### Requirement: Кэширование описаний

Система SHALL сохранять описания изображений в поле summary таблицы Message для повторного использования.

#### Scenario: Повторный запрос с тем же фото

**GIVEN** фото от Пользователя_А уже было распознано (summary заполнено)  
**AND** Пользователь_Б отправляет запрос "ио, что на этом фото?" как reply на сообщение А  
**WHEN** бот обрабатывает запрос Пользователя_Б  
**THEN** загружает сохранённое описание из summary  
**AND** НЕ вызывает vision API повторно  
**AND** НЕ расходует квоту IMAGE  
**AND** использует кэшированное описание в ответе

### Requirement: Обработка ошибок распознавания

Система SHALL возвращать зарезервированную квоту IMAGE при ошибке распознавания.

#### Scenario: Ошибка vision API

**GIVEN** квота IMAGE зарезервирована  
**WHEN** vision API возвращает ошибку (timeout, API error, etc.)  
**THEN** система вызывает releaseQuota(reservation)  
**AND** счётчик IMAGE восстанавливается  
**AND** ошибка пробрасывается выше для логирования

### Requirement: Статус typing поддерживается во время распознавания

Если запрос пользователя требует распознавания изображения и бот должен на него ответить, система MUST поддерживать Telegram-статус `typing` от начала подготовки запроса до появления ответа или завершения обработки. Обновления статуса MUST продолжаться во время поиска изображения, проверки квоты и вызова vision API.

#### Scenario: Распознавание фотографии в reply chain занимает много времени

- **GIVEN** пользователь отправил запрос к боту в reply chain с фотографией
- **WHEN** распознавание изображения занимает дольше срока действия одного статуса `typing`
- **THEN** Telegram получает повторные действия `typing` до завершения распознавания или начала ответа
- **AND** отдельное промежуточное сообщение не публикуется

#### Scenario: Пользователь отправил фотографию с запросом

- **GIVEN** пользователь отправил фотографию с подписью, требующей ответа бота
- **WHEN** система ожидает результат распознавания
- **THEN** Telegram получает повторные действия `typing` до появления ответа или ошибки

#### Scenario: Распознавание завершилось ошибкой

- **GIVEN** система уже выставляет статус `typing` для запроса с изображением
- **WHEN** vision API завершился ошибкой
- **THEN** система прекращает дальнейшие обновления `typing`
- **AND** существующая обработка ошибки и возврат квоты сохраняются

#### Scenario: Групповое фото не требует ответа

- **GIVEN** пользователь отправил фотографию в группе без обращения к боту
- **WHEN** система принимает сообщение
- **THEN** система не выставляет и не обновляет статус `typing`
- **AND** изображение не распознаётся

### Requirement: Vision-запрос не раскрывает Telegram credential

Система MUST загружать файл Telegram внутри доверенной границы приложения и MUST передавать vision-провайдеру байты либо безопасный объект без Telegram bot token. Bot token MUST NOT присутствовать в AI request body, URL, telemetry или error metadata.

#### Scenario: Фото отправляется на распознавание

- **WHEN** система получила `file_path` Telegram и вызывает vision API
- **THEN** приложение само загружает файл с Telegram и передаёт провайдеру содержимое без credential в URL

#### Scenario: Telegram download завершился ошибкой

- **WHEN** приложение не смогло получить байты изображения
- **THEN** vision API не вызывается, IMAGE-квота возвращается, а логи не содержат bot token
