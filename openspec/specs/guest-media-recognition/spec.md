# guest-media-recognition Specification

## Purpose

Распознавание фотографий и голосовых сообщений в гостевом режиме бота (Bot API 10.0, `guest_message`), когда бот отвечает в чужом чате через `answerGuestQuery` и не имеет доступа к истории чата глубже первого уровня reply.

## Requirements

### Requirement: Фото из запроса и из reply первого уровня

Система SHALL искать изображение для распознавания в самом гостевом запросе и в его непосредственном `reply_to_message`. Глубже первого уровня система MUST NOT ходить: в гостевом режиме у бота нет доступа к истории чата.

#### Scenario: Фото приаттачено к запросу

- **WHEN** пользователь отправляет гостевой запрос с фотографией и текстом `@bot опиши`
- **THEN** система распознаёт изображение из запроса
- **AND** расходует квоту IMAGE
- **AND** бот отвечает с описанием через `answerGuestQuery`

#### Scenario: Запрос reply на фото

- **WHEN** пользователь отправляет гостевой текстовый запрос `@bot что это?` как reply на сообщение с фото
- **THEN** система находит фото в `reply_to_message`
- **AND** распознаёт изображение
- **AND** расходует квоту IMAGE
- **AND** бот отвечает с описанием через `answerGuestQuery`

#### Scenario: Фото глубже первого уровня

- **WHEN** фото находится глубже непосредственного `reply_to_message` гостевого запроса
- **THEN** система его не ищет
- **AND** квота IMAGE НЕ расходуется
- **AND** бот отвечает без описания изображения

#### Scenario: Фото нет ни в запросе, ни в reply

- **WHEN** ни запрос, ни его `reply_to_message` не содержат фото
- **THEN** система НЕ вызывает vision API
- **AND** квота IMAGE НЕ расходуется

### Requirement: Кэш описаний гостевых фото

Система SHALL перед вызовом vision API проверять сохранённое описание (`summary`) сообщения с фото. При попадании в кэш система MUST NOT вызывать vision API повторно и MUST NOT расходовать квоту IMAGE.

#### Scenario: Повторный гостевой запрос к распознанному фото

- **WHEN** фото из `reply_to_message` уже было распознано (описание сохранено)
- **THEN** система использует сохранённое описание в ответе
- **AND** НЕ вызывает vision API повторно
- **AND** НЕ расходует квоту IMAGE

### Requirement: Голосовые сообщения и video note в гостях

Система SHALL распознавать голосовые сообщения и video note, приаттаченные к гостевому запросу либо находящиеся в его непосредственном `reply_to_message`. Распознанный текст передаётся в генерацию ответа как контекст.

#### Scenario: Войс приаттачен к запросу

- **WHEN** гостевой запрос содержит голосовое сообщение
- **THEN** система резервирует квоту VOICE
- **AND** распознаёт аудио через speech-провайдер
- **AND** использует транскрипт при генерации ответа

#### Scenario: Запрос reply на войс

- **WHEN** гостевой текстовый запрос отправлен как reply на голосовое сообщение
- **THEN** система находит аудио в `reply_to_message`
- **AND** распознаёт его с расходованием квоты VOICE
- **AND** использует транскрипт при генерации ответа

#### Scenario: Войс больше 20 MiB

- **WHEN** голосовой файл в гостевом запросе превышает 20 MiB (заявленный или фактический размер)
- **THEN** система НЕ скачивает и НЕ распознаёт файл
- **AND** возвращает квоту VOICE
- **AND** пользователь получает русскоязычное сообщение об ограничении через `answerGuestQuery`

#### Scenario: Ошибка распознавания войса

- **WHEN** speech-провайдер возвращает ошибку после резервирования квоты VOICE
- **THEN** система возвращает зарезервированную квоту
- **AND** ошибка пробрасывается для логирования

### Requirement: Лимитные ответы через answerGuestQuery

При отказе в квоте IMAGE или VOICE в гостевом режиме система SHALL отвечать коротким русскоязычным текстом через `answerGuestQuery` без кнопки подписки.

#### Scenario: Исчерпан лимит изображений

- **WHEN** квота IMAGE недоступна для гостевого запроса с фото
- **THEN** система отвечает `Лимит анализа изображений на сегодня закончился.` через `answerGuestQuery`
- **AND** vision API НЕ вызывается

#### Scenario: Исчерпан лимит голосовых

- **WHEN** квота VOICE недоступна для гостевого запроса с аудио
- **THEN** система отвечает коротким русскоязычным текстом об исчерпании лимита через `answerGuestQuery`
- **AND** распознавание НЕ запускается
