# quota-limits Specification

## Purpose

Определение и контроль дневных лимитов для различных типов запросов в Telegram боте: премиум-ответы AI (PRIMARY_RESPONSE), распознавание изображений (IMAGE), распознавание голосовых сообщений (VOICE), анализ контекста (ANALYSIS). Система управляет персональными квотами пользователей и групповыми квотами чатов, применяя финальные значения тарифных планов (платная подписка заменяет бесплатные лимиты, а не прибавляется к ним).

## Requirements

### Requirement: Финальные лимиты вместо суммирования

Система SHALL применять лимиты подписок как финальные значения, не прибавляя их к бесплатным лимитам.

#### Scenario: Пользователь без подписки

**GIVEN** пользователь не имеет активной подписки  
**WHEN** система проверяет доступные лимиты  
**THEN** возвращаются бесплатные лимиты: PRIMARY_RESPONSE=10, IMAGE=5, VOICE=10, ANALYSIS=1

#### Scenario: Пользователь с недельной подпиской

**GIVEN** пользователь имеет активную подписку WEEK  
**WHEN** система проверяет доступные лимиты  
**THEN** возвращаются лимиты подписки WEEK: PRIMARY_RESPONSE=30, IMAGE=15, VOICE=30, ANALYSIS=Infinity  
**AND** бесплатные лимиты НЕ прибавляются к платным

### Requirement: Закономерности лимитов

Система SHALL соблюдать математические закономерности между квотами.

#### Scenario: VOICE в 2 раза больше IMAGE (персональные)

**GIVEN** любой тариф с персональными лимитами  
**WHEN** проверяются лимиты IMAGE и VOICE  
**THEN** personal.VOICE = personal.IMAGE × 2

#### Scenario: PRIMARY равен IMAGE (групповые)

**GIVEN** любой тариф с групповыми лимитами  
**WHEN** проверяются лимиты PRIMARY_RESPONSE и IMAGE  
**THEN** chat.PRIMARY_RESPONSE = chat.IMAGE

#### Scenario: VOICE в 2 раза больше IMAGE (групповые)

**GIVEN** любой тариф с групповыми лимитами  
**WHEN** проверяются лимиты IMAGE и VOICE  
**THEN** chat.VOICE = chat.IMAGE × 2

### Requirement: Резервирование квоты

Система SHALL резервировать квоту перед выполнением операции и возвращать её при ошибке. Персональная квота резервируется для пользователя. Групповая квота, предоставленная подпиской чату, резервируется отдельно для каждого участника этого чата; один участник MUST NOT расходовать или блокировать квоту другого участника.

#### Scenario: Успешное резервирование

**GIVEN** пользователь имеет доступные лимиты IMAGE  
**WHEN** система запрашивает резервирование IMAGE
**THEN** система уменьшает счётчик доступных лимитов на 1  
**AND** возвращает `allowed=true`

#### Scenario: Возврат квоты при ошибке

**GIVEN** квота IMAGE зарезервирована  
**WHEN** операция распознавания изображения падает с ошибкой  
**THEN** система возвращает зарезервированную квоту  
**AND** счётчик доступных лимитов увеличивается на 1

#### Scenario: Независимые групповые квоты участников

**GIVEN** два пользователя используют один чат с активной групповой подпиской
**WHEN** первый пользователь расходует групповую квоту
**THEN** уменьшается только квота первого пользователя
**AND** доступная квота второго пользователя не изменяется

#### Scenario: Исчерпание квоты одного участника

**GIVEN** у первого пользователя закончилась выделенная ему групповая квота
**WHEN** второй пользователь запрашивает операцию в том же чате
**THEN** запрос второго пользователя может использовать его собственную групповую квоту

### Requirement: Фоновый анализ возвращает квоту до успешного результата

Система MUST считать операцию ANALYSIS успешной только после полного успешного завершения анализа и сохранения его результата. Любая наблюдаемая ошибка MUST переводить durable job в retry либо terminal failure и MUST возвращать зарезервированную ANALYSIS-квоту до следующей попытки. Повторная обработка одного source message MUST NOT повторно усиливать уже сохранённый факт.

#### Scenario: Временная ошибка анализа

- **WHEN** модель, база данных или fact analyzer завершают обработку ошибкой после резервирования ANALYSIS-квоты
- **THEN** ошибка не преобразуется в успешный пустой результат, квота возвращается, а durable job остаётся доступной для retry

#### Scenario: Повторная попытка успешна

- **WHEN** retry того же анализа успешно сохраняет результат
- **THEN** ANALYSIS-квота списана ровно один раз за успешную операцию, а job отмечена завершённой

#### Scenario: Ошибка после частичного сохранения

- **WHEN** первая попытка успела сохранить часть фактов и завершилась ошибкой
- **THEN** повторная попытка не увеличивает вес того же факта повторно для того же source message

#### Scenario: Исчерпаны повторные попытки

- **WHEN** durable job достигает terminal failure без успешного анализа
- **THEN** ANALYSIS-квота остаётся возвращённой, а причина отказа доступна в состоянии job и структурированных логах
