# Спецификация: Распознавание изображений только в треде запроса

## Обзор
Функция распознавания изображений (vision/image description) должна срабатывать только для изображений, находящихся в цепочке reply (треде) запроса пользователя к боту, а не для всех изображений в чате.

## Требования

### Основное поведение
- **Распознавание изображения происходит ТОЛЬКО если:**
  - Пользователь прислал изображение с текстовым запросом к боту (фото с подписью, начинающейся с "ио", или в личных сообщениях)
  - Пользователь отправил текстовый запрос к боту (начинается с "ио", реплай на сообщение бота, или личное сообщение) И в цепочке reply этого запроса есть изображение

- **Распознавание НЕ происходит если:**
  - Изображение отправлено в чат без подписи или с подписью, не являющейся запросом к боту
  - Изображение не находится в цепочке reply текущего запроса пользователя

### Определение цепочки reply
"Цепочка reply" (reply chain) означает последовательность сообщений, связанных через `reply_to_message`:
- Само сообщение пользователя (текст или фото с подписью)
- Сообщение, на которое пользователь ответил (`reply_to_message`)
- Сообщение, на которое ответило то сообщение (следующий уровень `reply_to_message`)
- И так далее вверх по цепочке до `maxDepth` (по умолчанию 10 уровней)

### Алгоритм поиска фото в цепочке
Функция `findPhotoInReplyChain`:
1. Начинает с `reply_to_message` текущего сообщения пользователя
2. Проверяет, есть ли фото в этом сообщении
3. Если нет - переходит к `reply_to_message` этого сообщения
4. Если `reply_to_message` недоступно через Telegram API - обращается к БД:
   - Находит `replyToMessageId` из таблицы `Message`
   - Загружает родительское сообщение
   - Проверяет поле `media` на наличие `image/jpeg`
5. Повторяет до тех пор, пока не найдет фото или не достигнет `maxDepth`
6. Возвращает `{ photo: PhotoSize, messageId: number }` или `null`

### Квота
- Распознавание изображения расходует квоту IMAGE
- Квота проверяется ПЕРЕД вызовом vision API
- Если квота исчерпана, пользователю отправляется уведомление о лимите
- Если распознавание упало с ошибкой, квота возвращается (releaseQuota)

## Текущая реализация

### Файлы
- `src/controllers/process-message.ts` - основная логика обработки сообщений
- `src/ai/image-description.ts` - функция описания изображений
- `src/shared/quota-service.ts` - управление квотами

### Функция findPhotoInReplyChain
```typescript
async function findPhotoInReplyChain(
  ctx: BotContext,
  startMessage: { message_id: number; photo?: PhotoSize[]; reply_to_message?: ... } | null,
  maxDepth = 10,
): Promise<{ photo: PhotoSize; messageId: number } | null>
```

Ходит по цепочке reply до тех пор, пока не найдет фото или не достигнет maxDepth.
Использует как Telegram API (ctx.msg.reply_to_message), так и БД (prisma.message).

### Хэндлеры
1. **`:text` хэндлер** (строки 173+)
   - Обрабатывает текстовые сообщения
   - Вызывает `findPhotoInReplyChain(ctx, ctx.msg.reply_to_message)` (строка 253+)
   - Резервирует квоту IMAGE только если фото найдено в цепочке
   - Корректно работает: описывает фото только если оно в reply-цепочке запроса к боту

2. **`:photo` хэндлер** (строки 293+)
   - Обрабатывает сообщения с фото
   - Проверяет `shouldRespond` ДО резервирования квоты (строка 326+)
   - Корректно работает: описывает только если фото в запросе к боту

## Ожидаемое поведение после реализации

### Сценарий 1: Фото с подписью-запросом
```
Пользователь: [фото] + "ио, что на картинке?"
Бот: [описывает изображение и отвечает]
```
✅ Распознавание происходит

### Сценарий 2: Фото в непосредственном реплае на запрос
```
Пользователь: ио, посмотри на это
└─ [реплай на чужое сообщение с фото]
Бот: [описывает изображение из реплая и отвечает]
```
✅ Распознавание происходит

### Сценарий 3: Фото через 3 уровня reply (новое!)
```
Пользователь_А: [фото] + "смотрите чего тут"
└─ Пользователь_Б: "да, интересно"
   └─ Пользователь_В: ио, расскажи что это
Бот: [находит фото от Пользователя_А в цепочке, описывает и отвечает]
```
✅ Распознавание происходит (фото найдено в reply-цепочке)

### Сценарий 4: Фото без запроса
```
Пользователь: [фото] + "вот моя собака"
```
❌ Распознавание НЕ происходит (нет запроса к боту)

### Сценарий 5: Фото не в цепочке reply запроса
```
Пользователь_А: [фото] + "смотрите"
Пользователь_Б: ио, расскажи о погоде  (БЕЗ реплая на фото)
Бот: [отвечает про погоду, не описывает фото от Пользователя_А]
```
❌ Распознавание НЕ происходит (фото не в цепочке reply)
