# Спецификация: Распознавание изображений только в треде запроса

## Обзор
Функция распознавания изображений (vision/image description) должна срабатывать только для изображений, находящихся в треде запроса пользователя к боту, а не для всех изображений в чате.

## Требования

### Основное поведение
- **Распознавание изображения происходит ТОЛЬКО если:**
  - Пользователь прислал изображение с текстовым запросом к боту (фото с подписью, начинающейся с "ио", или в личных сообщениях)
  - Пользователь отправил текстовый запрос к боту (начинается с "ио", реплай на сообщение бота, или личное сообщение) И в его реплае есть изображение

- **Распознавание НЕ происходит если:**
  - Изображение отправлено в чат без подписи или с подписью, не являющейся запросом к боту
  - Изображение не находится в треде текущего запроса пользователя

### Определение треда
"Тред" означает цепочку реплаев в Telegram:
- Само сообщение пользователя (текст или фото с подписью)
- Сообщение, на которое пользователь ответил (reply_to_message)
- Все сообщения связаны через message_thread_id (для топиков) или reply-цепочку

### Квота
- Распознавание изображения расходует квоту IMAGE
- Квота проверяется ПЕРЕД вызовом vision API
- Если квота исчерпана, пользователю отправляется уведомление о лимите
- Если распознавание упало с ошибкой, квота возвращается (releaseQuota)

## Текущая реализация

### Файлы
- `src/controllers/process-message.ts` - основная логика обработки сообщений
- `src/ai/image-description.ts` - функция описания изображений
- `src/shared/quota-service.ts` - управление квотами

### Хэндлеры
1. **`:text` хэндлер** (строки 94-216)
   - Обрабатывает текстовые сообщения
   - Проверяет `ctx.msg.reply_to_message?.photo` (строка 174)
   - Резервирует квоту IMAGE перед описанием (строки 183-192)
   - Корректно работает: описывает только если фото в реплае на запрос к боту

2. **`:photo` хэндлер** (строки 218-305)
   - Обрабатывает сообщения с фото
   - **ПРОБЛЕМА:** Резервирует квоту и описывает фото ДО проверки shouldRespond (строки 257-283)
   - Проверка shouldRespond происходит только на строке 285
   - **ИСПРАВЛЕНИЕ ТРЕБУЕТСЯ:** Проверять shouldRespond ПЕРЕД резервированием квоты и описанием

## Ожидаемое поведение после исправления

### Сценарий 1: Фото с подписью-запросом
```
Пользователь: [фото] + "ио, что на картинке?"
Бот: [описывает изображение и отвечает]
```
✅ Распознавание происходит

### Сценарий 2: Фото в реплае на запрос
```
Пользователь: ио, посмотри на это
└─ [реплай на чужое сообщение с фото]
Бот: [описывает изображение из реплая и отвечает]
```
✅ Распознавание происходит

### Сценарий 3: Фото без запроса
```
Пользователь: [фото] + "вот моя собака"
```
❌ Распознавание НЕ происходит (нет запроса к боту)

### Сценарий 4: Фото не в треде запроса
```
Пользователь_А: [фото] + "смотрите"
Пользователь_Б: ио, расскажи о погоде
Бот: [отвечает про погоду, не описывает фото от Пользователя_А]
```
❌ Распознавание НЕ происходит (фото не в треде запроса)

## Критерии приемки
- [ ] `:photo` хэндлер проверяет shouldRespond ПЕРЕД резервированием квоты IMAGE
- [ ] Квота IMAGE расходуется только для фото в треде запроса пользователя
- [ ] Существующие тесты проходят
- [ ] `bun run typecheck` проходит без ошибок
- [ ] Голосовые сообщения продолжают работать без изменений
