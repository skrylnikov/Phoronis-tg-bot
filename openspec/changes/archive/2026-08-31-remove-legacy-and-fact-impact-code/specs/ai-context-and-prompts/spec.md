## ADDED Requirements

### Requirement: Метаанализ использует UserFact без legacy JSON

Система MUST сохранить без замены текст текущей версии `meta-analyzer` из Langfuse, включая пять категорий `interests`, `communication_style`, `notable_traits`, `topics` и `notes`, правила увеличения `weight` для подтверждённых элементов и добавления новых элементов с `weight = 1`. Активный анализ пользовательских фактов MUST дополнительно сохранять действующий контракт результата с массивом `facts`, полями `content`, `type` и `sourceMessageId`; перенос промпта не MUST менять этот контракт. После подтверждённого переноса исторических данных система MUST хранить пользовательские факты в `UserFact` и MUST NOT поддерживать отдельный runtime- или migration-путь через legacy JSON `User.metaInfo`.

#### Scenario: Активный анализ извлекает факты

- **WHEN** плановая обработка запускает анализ сообщений пользователя
- **THEN** результат имеет действующий формат `facts`, а каждый новый факт сохраняет подтверждённый источник через `sourceMessageId`

#### Scenario: Историческая миграция завершена

- **WHEN** проверка данных подтверждает отсутствие неперенесённого `User.metaInfo`
- **THEN** приложение запускается и анализирует факты без legacy JSON и фоновой migration-задачи

## REMOVED Requirements

### Requirement: Текущая семантика метаанализа сохраняется

**Reason**: Старое требование сохраняет runtime-миграцию `User.metaInfo`, которая после подтверждённой сходимости больше не нужна; активный контракт метаанализа переносится в новое требование без legacy-пути.

**Migration**: До удаления подтвердить перенос всех исторических payload в `UserFact`; затем удалить JSON-поле и фоновую migration-задачу без изменения активного `facts`-контракта.
