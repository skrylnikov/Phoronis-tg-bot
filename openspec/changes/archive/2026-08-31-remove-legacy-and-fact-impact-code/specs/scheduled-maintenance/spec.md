## MODIFIED Requirements

### Requirement: Каждая плановая задача имеет собственный distributed lock

Система MUST использовать стабильный отдельный advisory lock для каждого типа плановой задачи. Два экземпляра одной задачи MUST NOT выполняться одновременно, а разные типы задач MUST NOT блокировать друг друга только из-за общего ключа.

#### Scenario: Два экземпляра запускают одну задачу

- **WHEN** два процесса одновременно запускают одинаковую плановую задачу
- **THEN** ровно один процесс выполняет работу, а второй фиксирует пропущенный запуск

#### Scenario: Совпали расписания разных задач

- **WHEN** одновременно запускаются очистка private-сообщений и другая действующая плановая задача
- **THEN** обе задачи могут выполняться независимо

## REMOVED Requirements

### Requirement: Maintenance сходится с ограниченным объёмом работы

**Reason**: Единственными сценариями требования были удаляемый пересчёт fact impact и завершённая одноразовая миграция `User.metaInfo`; сохранять runtime-контур ради отсутствующей работы не требуется.

**Migration**: До удаления runtime-миграции подтвердить отсутствие непустого `User.metaInfo`. Fact-impact данные не переносятся, поскольку контур не создаёт достоверные события использования и реакций.
