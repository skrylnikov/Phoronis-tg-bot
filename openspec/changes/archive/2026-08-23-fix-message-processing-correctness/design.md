## Context

Message pipeline уже имеет reply-chain traversal, durable analysis jobs и private mode, но в трёх местах потеряна сквозная семантика: корневая DB-запись завершается до проверки media, `null` скрывает сбой анализа от job runner, а AI response сохраняется без private-признака. Исправления пересекают controller, domain и persistence, но не требуют новой архитектуры или схемы данных.

## Goals / Non-Goals

**Goals:**

- находить фото в корне DB fallback в пределах `maxDepth`;
- возвращать ANALYSIS-квоту и повторять неуспешный анализ;
- не усиливать один факт повторно при retry того же source message;
- одинаково применять private mode к входящему сообщению и ответу бота.

**Non-Goals:**

- переписывать общий message pipeline;
- менять размеры или порядок расходования квот;
- мигрировать исторические bot responses, ранее сохранённые как неприватные;
- менять срок хранения private mode.

## Decisions

### Decision: Текущее DB-сообщение проверяется до перехода к родителю

Reply traversal сохраняет текущий цикл и `maxDepth`, но порядок внутри DB fallback становится: загрузить запись → проверить `media`/`summary` → при отсутствии результата проверить `replyToMessageId` → перейти к родителю либо завершиться. Это устраняет дефект одной перестановкой без отдельного graph abstraction.

### Decision: Ошибка анализа остаётся ошибкой до job runner

Fact analyzer логирует контекст и пробрасывает ошибку вместо возврата `null`. Application handler освобождает reservation в `catch`, после чего повторно пробрасывает ошибку; существующий durable runner назначает retry или terminal failure. Пустой валидный ответ модели остаётся успешным результатом и отличается от исключения.

### Decision: Retry идемпотентен относительно source message

Перед увеличением веса существующего факта persistence проверяет, был ли тот же source message уже учтён этим фактом. Повторная попытка может завершить недостающие записи, но не должна повторно усиливать сохранённые до сбоя факты. Используются существующие source/history данные; новая таблица или отдельный ledger не вводятся.

### Decision: Private-признак передаётся в единый путь сохранения AI response

Определённый controller-ом private mode передаётся в AI response persistence и применяется для text/photo/voice flows. Репозиторные фильтры и семидневная очистка уже работают по private-признаку, поэтому отдельные ветки фильтрации не добавляются.

## Risks / Trade-offs

- [Частично сохранённый анализ повторяется] → source-aware идемпотентность предотвращает двойное усиление; тест покрывает сбой между фактами.
- [Проброс ошибок увеличит число retry] → используются существующие backoff и terminal state, а структурированный лог различает временный и окончательный отказ.
- [Исторические ответы остаются видимыми для retrieval] → автоматическая переклассификация небезопасна без достоверного признака; scope действует только на новые ответы.
- [Voice flow может иметь отдельный путь] → regression-тесты должны пройти для text, photo и voice, а признак устанавливается максимально близко к общей persistence boundary.

## Migration Plan

1. Добавить unit/regression-тесты, воспроизводящие три дефекта.
2. Изменить порядок DB traversal и error propagation/idempotence.
3. Передать private-признак во все AI response flows.
4. Выполнить focused tests, полный test suite, typecheck и lint.
5. Откат не требует миграции данных, но вернёт прежние дефекты для новых сообщений.
