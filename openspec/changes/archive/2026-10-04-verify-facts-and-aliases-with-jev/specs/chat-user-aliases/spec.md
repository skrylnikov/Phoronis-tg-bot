# Spec Delta

## MODIFIED Requirements

### Requirement: Автоматическое наблюдение имеет проверяемый источник

Система MUST извлекать псевдоним, адресата и уверенность модели только из доступных публичных пользовательских сообщений и их публичного контекста. Адресат MUST принадлежать переданному набору известных пользователей, псевдоним MUST присутствовать в исходном тексте после нормализации, а источник MUST существовать в текущем чате и анализируемом наборе. Оценки вне `[0, 1]`, нечисловые значения и уверенность ниже `0.5` MUST NOT сохраняться. Система MUST NOT считать собственные ответы бота источниками и MUST NOT назначать псевдоним по одному факту reply без смысловой связи.

#### Scenario: Обращение в reply
- **WHEN** пользователь отвечает Александру «Санёк, привет», модель извлечения выделяет обращение к Александру с confidence `0.85`, источник и ID проверены, а Jev подтверждает принадлежность с вероятностью `0.95`
- **THEN** система сохраняет наблюдение связи «Санёк → Александр» с вероятностью принадлежности Jev `0.95`
- **AND** одно наблюдение остаётся кандидатом без независимого подтверждения

#### Scenario: Reply содержит третье лицо
- **WHEN** в reply Ивану написано «передай Саше привет», а принадлежность имени конкретному известному Саше не установлена
- **THEN** система не назначает Ивану псевдоним «Саша» и пропускает неоднозначное наблюдение

#### Scenario: Модель придумала ID или источник
- **WHEN** наблюдение содержит неизвестный ID, отсутствующее сообщение или псевдоним, которого нет в исходном тексте
- **THEN** система пропускает это наблюдение без сохранения связи и без потери других валидных наблюдений и фактов

#### Scenario: Бот повторил собственную догадку
- **WHEN** бот сам использовал имя «Санёк» в ответе
- **THEN** ответ не создаёт наблюдение и не усиливает уверенность

## ADDED Requirements

### Requirement: Jev независимо проверяет автоматическое наблюдение
Система MUST проверять принадлежность кандидата конкретному участнику по публичному источнику и отдельно пригодность для уважительного обращения. Для принятого evidence MUST использоваться вероятность принадлежности Jev; её MUST NOT подменять метрикой confidence выбранного варианта. Действующие правила агрегирования, квот и предпочтений владельца MUST сохраняться.

#### Scenario: Упоминание третьего лица в reply
- **WHEN** в reply написано «передай Саше привет», а LLM назначила адресату псевдоним «Саша»
- **THEN** Jev не подтверждает принадлежность лишь по наличию reply и evidence не сохраняется

#### Scenario: Принадлежность подтверждена, обращение сомнительно
- **WHEN** вероятность принадлежности проходит порог, а пригодность обращения не проходит отдельный порог
- **THEN** связь может накапливать evidence для поиска, но наблюдение помечается непригодным для автоматического обращения

#### Scenario: Явное решение владельца
- **WHEN** владелец явно задаёт, запрещает или отклоняет псевдоним
- **THEN** действующий инструмент применяет решение немедленно без ожидания фоновой проверки Jev
