## Context

См. `proposal.md` для мотивации изменения. Сейчас AI-tools регистрируются в `src/ai/chat-generation.ts`; там уже есть read-only и обычный набор инструментов, а сетевые tools используют встроенный `fetch` и сигнал отмены текущего Telegram-update. Пользовательский текст, включая URL, уже передаётся в контекст генерации. Конфигурация приложения сейчас содержит обязательные переменные, поэтому ключ Firecrawl нельзя добавлять как безусловную проверку запуска.

## Goals / Non-Goals

**Goals:**

- Дать модели две понятные операции: прочитать страницу по URL и выполнить web-поиск.
- Использовать Firecrawl v2 REST API через уже имеющийся `fetch`, без обязательной новой npm-зависимости.
- Передавать модели компактный, структурированный и ограниченный результат с источниками.
- Сохранить работу обычных ответов при отсутствии ключа или временной ошибке Firecrawl.
- Сделать web-доступ read-only и доступным в существующих read-only потоках.

**Non-Goals:**

- Авторизация на сайтах, использование пользовательских cookies и обход paywall.
- Полноценная браузерная автоматизация, интерактивный клик, заполнение форм и обход CAPTCHA.
- Crawl целого сайта, долговременное индексирование и сохранение веб-контента в PostgreSQL.
- Отдельная тарифная квота `WEB` и изменение тарифных планов в MVP.
- Доверие инструкциям, найденным в HTML, Markdown или результатах поиска.

## Decisions

### Два инструмента вместо одного универсального

Создаются `read_web_page` и `search_web`. Разделение отражает два пользовательских сценария и позволяет модели явно выбрать действие: ссылка пользователя читается напрямую, а поиск сначала возвращает ограниченные метаданные результатов. Один универсальный tool с режимом `url/query` был бы короче по API, но менее прозрачен для модели и сложнее ограничивается.

### Firecrawl v2 через встроенный fetch

Адаптер вызывает `POST https://api.firecrawl.dev/v2/scrape` с форматом Markdown для чтения страницы и `POST https://api.firecrawl.dev/v2/search` для поиска. Для scrape используется основной контент страницы; search по умолчанию получает заголовки, описания и URL. Полный Markdown всех результатов не запрашивается автоматически: выбранные страницы читаются отдельным вызовом, чтобы не раздувать контекст.

Ключ передаётся только в `Authorization: Bearer ...`. В коде не используется Firecrawl SDK: существующий runtime уже предоставляет `fetch`, а добавление SDK не даёт MVP дополнительных возможностей.

### Опциональный ключ и условная регистрация

`FIRECRAWL_API_KEY` читается как необязательная настройка. При отсутствии ключа web-tools исключаются из набора инструментов до вызова модели. Это сохраняет совместимость локальной разработки, тестов и окружений, где интернет-функция не включена.

### Ограниченный результат tool

Адаптер возвращает модели только структурированные поля: тип операции, URL источника, заголовок, описание/Markdown с ограниченной длиной, финальный URL и безопасное состояние ошибки. Полный HTML, raw headers, токен и диагностический payload Firecrawl не передаются модели и не пишутся в обычный лог.

Ограничения задаются в одном месте адаптера: разрешённые схемы URL, таймаут, максимальный размер результата и максимальное число web-вызовов в рамках одной генерации. Текущий общий `stepCountIs(5)` остаётся дополнительным предохранителем, но не заменяет web-лимит.

### Защита от prompt injection

Инструкции для модели явно отделяют внешний текст от системных правил и пользовательских указаний. Результат страницы считается данными: он может содержать текст вроде «игнорируй предыдущие инструкции», но такой текст не получает полномочий. Ошибки логируются только через существующую безопасную сериализацию, без URL-секретов, полных prompt-ов и содержимого страницы.

### Квота и хранение

В MVP web-вызовы расходуют обычную квоту основного AI-ответа и ограничиваются числом операций на один ответ. Новая квота и Prisma-модель не добавляются. Если стоимость Firecrawl потребует независимого биллинга, это будет отдельное изменение со спецификацией тарифов.

## Risks / Trade-offs

- **[Стоимость и размер контекста]** Полный текст нескольких страниц дорог и может переполнить контекст → сначала возвращать метаданные поиска и читать только выбранные источники; всегда ограничивать Markdown.
- **[Prompt injection во внешнем тексте]** Страница может содержать инструкции, маскирующиеся под системные → считать весь web-результат недоверенными данными и добавить регрессионный тест.
- **[Недоступность или rate limit Firecrawl]** Внешний API может отвечать 4xx/5xx или 429 → возвращать безопасную ошибку, сохранять обычный AI-flow и не списывать отдельную web-квоту, которой в MVP нет.
- **[Неполное извлечение]** Динамический или закрытый сайт может вернуть мало текста → сообщать об ограниченности источника, не выдавая предположение за прочитанный факт.
- **[Передача пользовательского запроса третьей стороне]** URL и поисковый запрос отправляются Firecrawl → не передавать секреты и приватные данные из контекста, а в пользовательском ответе указывать источники; авторизация на сайтах не поддерживается.

## Migration Plan

1. Добавить необязательную переменную `FIRECRAWL_API_KEY` в пример окружения и конфигурационный слой.
2. Добавить адаптер и tools, затем условно включить их в существующие наборы read-only и обычной генерации.
3. Выполнить unit-тесты с замокированным `fetch`; реальные запросы к Firecrawl не включать в обычный тестовый suite.
4. Развернуть без миграции базы данных. При отсутствии ключа поведение должно совпадать с предыдущим.
5. Для rollback удалить регистрацию web-tools или отключить ключ; схема базы и сохранённые сообщения при этом не меняются.
