## Purpose

Задаёт безопасную настройку приветствия группы и предсказуемую отправку этого приветствия новым участникам без доверия к идентификаторам, предложенным моделью.

## ADDED Requirements

### Requirement: Приветствие изменяет только текущий администратор

Система MUST разрешать изменение приветствия только реальному отправителю текущего update, если Telegram подтверждает его статус администратора или владельца текущей группы. Идентификаторы чата и пользователя из текста, AI-аргументов или сохранённого контекста MUST NOT заменять идентификаторы текущего запроса.

#### Scenario: Администратор меняет приветствие своей группы

- **WHEN** текущий отправитель является администратором текущей группы и задаёт допустимый текст
- **THEN** система сохраняет приветствие только для этой группы

#### Scenario: Обычный участник указывает ID администратора

- **WHEN** текущий отправитель не администратор, но AI-аргументы содержат ID другого администратора
- **THEN** система отказывает и не изменяет ни один чат

#### Scenario: Запрошен другой чат

- **WHEN** AI-аргументы или текст содержат ID чата, отличный от текущего
- **THEN** система игнорирует этот ID и не изменяет другой чат

### Requirement: Текст приветствия ограничен Telegram

Система MUST принимать непустое приветствие длиной не более 4096 символов и MUST возвращать русскоязычную ошибку валидации без изменения сохранённого значения при нарушении ограничения.

#### Scenario: Приветствие слишком длинное

- **WHEN** администратор задаёт текст длиннее 4096 символов
- **THEN** система не сохраняет его и сообщает об ограничении

### Requirement: Настроенное приветствие доставляется актуальному участнику

Система MUST читать только существующие поля настройки чата и MUST отправлять сохранённое приветствие, если после короткой задержки хотя бы один новый пользователь всё ещё является участником группы. Ошибка чтения настроек или проверки membership MUST NOT приводить к отправке неподтверждённого приветствия.

#### Scenario: Новый пользователь остался в группе

- **WHEN** Telegram подтверждает membership нового пользователя после задержки и приветствие настроено
- **THEN** бот отвечает сохранённым приветствием на service message

#### Scenario: Новый пользователь сразу вышел

- **WHEN** Telegram сообщает статус `left` или `kicked`
- **THEN** бот не отправляет приветствие

#### Scenario: Приветствие не настроено

- **WHEN** у текущей группы отсутствует текст приветствия
- **THEN** обработчик завершается без Telegram-сообщения и без runtime-ошибки
