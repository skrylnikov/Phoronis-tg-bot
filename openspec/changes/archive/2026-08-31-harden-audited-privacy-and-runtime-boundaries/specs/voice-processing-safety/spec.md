## Purpose

Ограничивает локальную обработку голосового медиа и срок жизни временных объектов, чтобы распознавание не удерживало лишние пользовательские данные и не создавало неконтролируемую нагрузку на процесс.

## ADDED Requirements

### Requirement: Входное voice-медиа имеет жёсткий предел

Система MUST отклонять voice или video note размером более 20 MiB до полной загрузки в память. Если Telegram не сообщил размер заранее, система MUST прекратить чтение после достижения того же предела. Квота VOICE при таком отказе MUST быть возвращена, а пользователь MUST получить русскоязычное сообщение.

#### Scenario: Telegram сообщил слишком большой файл

- **WHEN** `file_size` превышает 20 MiB
- **THEN** система не скачивает и не перекодирует файл, возвращает квоту и сообщает об ограничении

#### Scenario: Фактический ответ больше заявленного

- **WHEN** поток скачивания превышает 20 MiB
- **THEN** система отменяет чтение до создания полного буфера и не запускает распознавание

### Requirement: Provider logging не включается приложением

Система MUST NOT отправлять внешнему speech-провайдеру заголовок или параметр, явно разрешающий хранение пользовательских аудиоданных для логирования или обучения.

#### Scenario: Короткое аудио отправляется на синхронное распознавание

- **WHEN** приложение формирует запрос speech API
- **THEN** запрос не содержит opt-in на provider data logging

### Requirement: Временный объект удаляется после распознавания

Система MUST использовать уникальный object key для каждого long-running распознавания и MUST пытаться удалить объект в `finally` после успеха, ошибки, timeout или отмены. Ошибка удаления MUST быть отдельным наблюдаемым событием и MUST NOT маскировать исходный результат распознавания.

#### Scenario: Long-running распознавание успешно

- **WHEN** текст получен от speech API
- **THEN** временный аудиообъект удаляется до завершения операции

#### Scenario: Распознавание отменено

- **WHEN** update теряет lease или процесс отменяет операцию после загрузки объекта
- **THEN** приложение всё равно выполняет попытку удаления этого object key

#### Scenario: Storage не принял удаление

- **WHEN** удаление временного объекта завершилось ошибкой
- **THEN** исходная ошибка или результат распознавания сохраняется, а cleanup failure фиксируется отдельно без содержимого аудио
